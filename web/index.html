Real-time collaborative editing for VimVim のためのリアルタイム共同編集

寄せ書きyosegaki

Share a buffer. Let people in. Write together, each in your own Vim, with your own config, keys and plugins. バッファを共有して、仲間を招き入れて、一緒に書く。それぞれが自分の Vim、自分の設定、自分のキーバインドのままで。

Merged, not lockedロックせずにマージ

    
Everyone types at once. Edits are merged with operational transformation, so all buffers end up with the same text, even when two people type on the same line.全員が同時に打てます。編集は Operational Transformation でマージされるので、同じ行を同時に触っても、最後は全員のバッファが同じ内容になります。

  

  

    
The host decides決めるのはホスト

    
Public sessions can be watched by anyone with the link. Private ones wait at the door. Nobody edits until the host says yes, and the server enforces it.public ならリンクを知っている人は誰でも閲覧でき、private なら入室にも承認が必要です。ホストが許可するまで誰も編集できず、それはサーバ側で強制されます。

  

  

    
See each otherお互いが見える

    
Other people's cursors show up in their own colors with their names, so you always know who is where.他の人のカーソルが、色と名前付きで表示されます。誰がどこを触っているかが一目でわかります。

  

  

    
Plain Vim script素の Vim script

    
The plugin is legacy Vim script built on channels, text properties and popups. No Python, no Lua, no patches to Vim.プラグインは channel、text property、popup を使った legacy Vim script だけで書かれています。Python も Lua も、Vim へのパッチも不要です。

Why a bridge?なぜ中継役が要るのか

      
Vim channels speak raw TCP, not TLS or WebSocket. So the plugin starts yosegaki connect as a job and talks JSON to it over stdin and stdout. The bridge does the TLS and WebSocket part, using the certificate store of your OS. It is the same binary as the server, so everyone just installs yosegaki.Vim の channel は生の TCP しか話せず、TLS も WebSocket も扱えません。そこでプラグインは yosegaki connect を job として起動し、標準入出力で JSON をやり取りします。TLS と WebSocket は中継役が担当し、証明書の検証には OS の証明書ストアを使います。サーバと同じバイナリなので、全員が yosegaki を1つ入れるだけです。

    

    

      
Why it convergesなぜ食い違わないのか

      
Each edit is sent as an operation (retain, insert, delete) against a known revision. The server puts operations in order and transforms late ones against what happened in between. Clients transform incoming edits against their own unconfirmed ones. Every buffer ends up with the same text.編集は「どのリビジョンに対する、保持・挿入・削除か」という操作として送られます。サーバは操作に順番を付け、遅れて届いた操作を、その間に起きた操作に合わせて変換します。クライアントも、届いた操作を自分の未確認の編集に合わせて変換します。こうして全員のバッファが同じ内容に収束します。

:YosegakiShare private yosegaki.compile-error.net
" a join link is shown; send it to your guests

" approve people (IDs are in :YosegakiStatus)

:YosegakiAllow 3 view
:YosegakiDeny 4

" viewers can ask to edit

Run your own server自分でサーバを立てる

  

    

      
docker run -d -p 8080:8080 ghcr.io/mattn/yosegaki

      
A static binary on a scratch image, running as a non-root user. Sessions live in memory, so run one instance.scratch イメージに静的バイナリを1つだけ置いたコンテナで、root 以外のユーザで動きます。セッションはメモリ上にあるので、インスタンスは1つで動かしてください。

    

    

      
yosegaki serve -addr :8080

      
Put it behind anything that terminates TLS and passes WebSockets. The server pings every 30 seconds so idle sessions survive proxies such as Cloudflare.TLS を終端して WebSocket を通すプロキシの後ろに置いてください。サーバは30秒ごとに ping を送るので、Cloudflare のようなプロキシ越しでもアイドル中のセッションが切れません。
